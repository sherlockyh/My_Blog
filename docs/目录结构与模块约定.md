# 目录结构与模块约定

本文是仓库的结构约定速查：新增模块/页面/组件时按此放置，保持全仓一致。

## 总览

pnpm + turbo monorepo，三个包：

```
apps/server            NestJS 后端（Prisma + PostgreSQL + Redis + MinIO）
apps/web               React SPA（Vite + antd + zustand）
packages/shared        前后端共享 DTO（纯类型，无运行时代码）
```

## 后端（apps/server）

```
prisma/                schema.prisma + migrations/ + seed.ts（三者同层）
src/
├── main.ts            启动与全局中间件（CSP/CORS 从 ConfigService 组装）
├── app.module.ts      根模块：全局 APP_GUARD / APP_INTERCEPTOR / APP_FILTER
├── common/            跨模块横切能力（全部可被业务模块直接引用）
│   ├── audit/         审计（全局拦截器 + @AuditAction 装饰器 opt-in）
│   ├── guards/        JwtGuard、RateLimitGuard（全局注册 + @RateLimit opt-in）
│   ├── prisma/ redis/ 全局单例，@Global 模块
│   ├── config/        AppConfig 接口 + 启动期校验（环境变量唯一契约）
│   └── dto/ errors/ filters/ interceptors/ types/ utils/
└── modules/           业务模块，统一最小模板：
    └── <name>/
        ├── <name>.module.ts
        ├── <name>.service.ts      # 直连 PrismaService，不再设 repository 壳
        ├── controllers/           # 薄封装，一个公开一个 admin 可并存
        └── dto/
```

**约定：**

- 新业务模块一律用最小模板。只有查询复杂到需要独立测试（如 article 的
  keyset 分页、slug 冲突重试）才允许加 `repositories/`，且需在模块内注明理由。
- 环境变量只在 `common/config/config.validation.ts` 声明、在注入处用
  `ConfigService<AppConfig>` 读取；**禁止在业务代码里直读 `process.env`**。
- 限流与审计都是「全局注册 + 装饰器开启」：给路由加 `@RateLimit({...})` /
  `@AuditAction({...})` 即生效，不需要（也不要）再挂 `@UseGuards`/`@UseInterceptors`。
- Prisma Json 列的类型转换只走 `common/utils/json.ts`（`isRecord`/`asJson`）。
- 测试与源码同目录（`*.spec.ts`），e2e 在 `test/`；跑 `pnpm --filter @my-blog/server test`。

## 前端（apps/web）

```
src/
├── blog/              前台域（访客侧的全部代码）
│   ├── pages/         页面；私有组件就近放 pages/<page>/components/
│   ├── components/    前台域组件（Navbar、ArticleCard、ProjectCard…）
│   ├── layout/        PublicLayout
│   └── routes.tsx     前台路由 + 路由级 lazy 声明
├── admin/             后台域（管理侧的全部代码）
│   ├── pages/         管理页；私有组件就近放
│   ├── components/    后台通用件（ListPage、AdminThemeProvider…）
│   ├── layout/        AdminLayout
│   ├── hooks/         usePagedList（admin 分页）
│   └── routes.tsx     后台路由 + 路由级 lazy 声明
├── components/common/ 跨域通用 UI，无业务语义（ErrorBoundary、CodeBlock…）
├── router/            聚合两个域的 routes 并注册兜底重定向
├── services/          全部 HTTP 请求（按域拆文件），外部 API 也收在这里
├── hooks/             useRequest（跨域数据请求）
├── store/             zustand（auth/theme/site/adminDirty）
├── utils/ styles/ i18n/
```

**约定：**

- 新增页面/组件先判定归属域：前台进 `blog/`、后台进 `admin/`、
  业务无关且跨域的进 `components/common/`；不确定归哪个域时说明它
  不该存在依赖歧义。两个域之间不互相 import，共享走 common 或更下层。
- 组件不直接发请求：数据获取一律 `useRequest`（前台）或 `usePagedList`
  （admin 列表），fetcher 调 services 层函数。加载失败要渲染错误态
  （`common.loadFailed` + retry），不许 `catch(() => setXxx([]))` 静默吞错。
- 全量型派生数据（归档、分类树、相关文章）用 `articleApi.allPublished()`，
  不要用分页接口拉大页码模拟全量。
- i18n 新增命名空间时在 `locales/{zh,en}/` 下按现有子文件拆分，
  两语言 key 必须对称。
- CSP 由 vite `injectCsp` 插件按环境注入；跨域 API 用 `VITE_CSP_CONNECT_SRC`
  追加，不要在 index.html 手写。

## 工程护城河

- 提交前 husky + lint-staged 自动对暂存文件跑 eslint --fix 与 prettier。
- CI（.github/workflows/ci.yml）：Lint → Test → Typecheck → Build。
- 后端 tsconfig 全 strict，前端 strict + 0 any；新增代码不得引入 `any`。
