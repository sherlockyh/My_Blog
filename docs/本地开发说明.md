# 本地开发说明

> 适用范围：本地开发、联调和本地故障排查。生产部署请看 [上线说明文档](上线说明文档.md)。

## 1. 前置条件

```text
Node.js >= 20
pnpm 9+
Docker
```

首次进入项目后安装依赖：

```bash
pnpm install
```

## 2. 配置文件职责

项目有三类环境配置，不要混用：

| 文件               | 使用场景            | 主要内容                                    |
| ------------------ | ------------------- | ------------------------------------------- |
| `.env`             | Docker Compose      | 宿主机端口、管理员账号、JWT、MinIO 根凭证   |
| `apps/server/.env` | 本地直接运行 NestJS | `localhost` 数据库、Redis、MinIO 和后端端口 |
| `apps/web/.env`    | 前端构建期          | API 地址和 CSP 追加来源，通常可不配置       |

创建模板：

```bash
cp .env.example .env
cp apps/server/.env.example apps/server/.env
```

### 2.1 本地后端配置

`apps/server/.env` 至少确认以下地址使用 `localhost`：

```ini
DATABASE_URL=postgresql://blog:blog123@localhost:5432/my_blog
REDIS_URL=redis://localhost:6379
PORT=7001
CORS_ORIGIN=http://localhost:5173
S3_ENDPOINT=http://localhost:9000
S3_BUCKET=my-blog
```

`S3_ACCESS_KEY` 和 `S3_SECRET_KEY` 要与根目录 `.env` 中的 MinIO 根账号和密码对应。

### 2.2 管理员账号

后端启动时，如果 `User` 表为空，会按以下配置创建管理员：

```text
ADMIN_USERNAME
ADMIN_PASSWORD
```

已有管理员时，修改环境变量不会自动修改数据库中的密码。示例配置中的 `admin/admin123` 只用于本地开发，不能用于生产。

## 3. 标准启动流程

```bash
pnpm db:up
pnpm db:push
pnpm db:seed
pnpm dev
```

每条命令的作用：

| 命令           | 作用                               |
| -------------- | ---------------------------------- |
| `pnpm db:up`   | 启动 PostgreSQL、Redis、MinIO      |
| `pnpm db:push` | 根据 Prisma Schema 同步本地数据库  |
| `pnpm db:seed` | 写入示例文章、项目、资源和站点配置 |
| `pnpm dev`     | 通过 Turborepo 同时启动前端和后端  |

访问地址：

```text
前台：http://localhost:5173
后台：http://localhost:5173/admin/login
后端：http://localhost:7001
MinIO API：http://localhost:9000
MinIO 控制台：http://localhost:9001
```

## 4. 分开启动和常用命令

只启动前端：

```bash
pnpm dev:web
```

只启动后端：

```bash
pnpm dev:server
```

停止基础服务：

```bash
pnpm db:down
```

`pnpm db:down` 默认不会删除数据卷。不要把下面的命令当作普通重启命令：

```bash
docker compose down -v
```

`-v` 会删除 Compose 数据卷，可能导致 PostgreSQL 数据、Redis 数据和 MinIO 文件丢失。

本地检查：

```bash
pnpm typecheck
pnpm build
pnpm lint
```

## 5. 本地请求链路

### 5.1 API 请求

前端默认请求 `/api`，Vite 将它代理到 NestJS：

```text
浏览器 /api/...
  → Vite :5173
  → NestJS :7001
```

NestJS 的全局前缀也是 `/api`，所以本地不要把前端请求写成 `/auth/login`，应使用：

```text
/api/auth/login
```

### 5.2 上传文件

前端上传接口：

```text
POST /api/admin/upload
```

上传成功后默认返回：

```text
/uploads/时间戳-UUID.png
```

Vite 会将 `/uploads/` 代理到 MinIO 的：

```text
http://localhost:9000/my-blog/uploads/
```

### 5.3 后端返回结构

后端成功响应统一包装为：

```json
{
  "code": 0,
  "data": {},
  "message": "ok"
}
```

前端 Axios 封装会自动取出 `data`。因此页面服务层通常直接得到业务数据，不需要再次访问 `response.data.data`。

## 6. 常见问题

### 6.1 端口被占用

默认端口：

```text
5173：Vite
7001：NestJS
5432：PostgreSQL
6379：Redis
9000：MinIO API
9001：MinIO 控制台
```

先确认占用端口的进程，再决定是否停止进程或调整配置。不要只修改前端端口而忘记同步 `CORS_ORIGIN`。

### 6.2 修改管理员密码后没有生效

这是设计行为：管理员只在 `User` 表为空时自动创建。已有账号需要通过数据库或后续密码修改功能处理，不能依赖重新启动服务覆盖。

### 6.3 图片上传成功但页面打不开

按顺序检查：

1. MinIO 容器是否健康；
2. `my-blog` 桶是否存在；
3. `my-blog/uploads/` 下是否有对象；
4. 返回路径是否为 `/uploads/...`；
5. Vite `/uploads` 代理是否仍指向 `localhost:9000`；
6. 浏览器控制台是否有 CSP 错误。

### 6.4 文章保存返回 413

当前后端 JSON 请求体上限为 `32kb`，配置在：

```text
apps/server/src/main.ts
```

较长 Markdown 文章可能超过限制。Nginx 的上传限制不能解决 NestJS JSON 解析器的限制。

### 6.5 `ready` 检查失败

检查：

```bash
curl http://localhost:7001/api/health/live
curl http://localhost:7001/api/health/ready
docker compose logs --tail=200 postgres redis
```

`live` 只表示 NestJS 进程存活；`ready` 还会检查 PostgreSQL 和 Redis。

## 7. 本地数据重置原则

普通重启：

```bash
pnpm db:down
pnpm db:up
```

只重建数据库结构时，优先使用：

```bash
pnpm db:push
```

需要彻底清空本地数据时，先确认没有需要保留的数据，再单独执行带 `-v` 的 Compose 命令。该操作不可作为日常排查步骤。
